## 🎮 Project Overview

**SURVIVAL FORCE** is an independent game development project aiming to
create an Android survival shooter with a battle royale-style
experience. The project takes inspiration from the excitement and
atmosphere of classic mobile battle royale games while building its own
project identity and implementation.

The goal is to develop an action-focused experience in which players
explore a battlefield, find useful resources, face opponents, and try to
survive. The project is intended for Android and is associated with
**Unreal Engine 5.4** and **C++**.

Development includes project validation, gameplay implementation,
Android packaging, and testing on real devices. A source file,
configured setting, or asset does not by itself prove that a feature
works in the running game; each feature and build must be verified
separately.

> **Our principle:** build carefully, test honestly, and only claim what
> has actually been verified.

## ⚔️ Game Details

SURVIVAL FORCE is being developed around the core ideas of survival,
tactical movement, combat, and exploration. The aim is to create a
mobile-friendly game experience that feels exciting and readable on a
touchscreen.

The following describes the intended game direction; it does **not**
mean every feature is already implemented or playable.

### 🔫 Combat and Weapons

The game aims to include action-focused combat, responsive shooting, and
clear feedback during encounters. Weapon behavior, aiming, firing, hit
feedback, and balance will need to be implemented and tested as
development progresses.

### 🎒 Loot and Equipment

Resource collection and equipment are intended to give players reasons
to explore and prepare before engaging opponents. Any loot, inventory,
or equipment system should be marked complete only after it works in a
running build.

### 🌍 Battlefield and Exploration

The intended experience includes a battlefield where players can move
around, explore, choose their routes, and encounter opponents.
Environments should support readable navigation and gameplay rather than
being only visual backdrops.

### 🪂 Survival Gameplay

Survival is the central theme: stay alert, manage available resources,
choose when to engage, and try to remain alive. Match flow and win
conditions will depend on the gameplay systems implemented in the
project.

### 🤖 AI Opponents

AI-controlled opponents may be developed to support combat and practice
gameplay where the project systems allow it. Their behavior and
reliability must be verified in actual gameplay before being described
as complete.

### 📱 Mobile Controls

The game is intended for Android, so touch controls, button size, camera
movement, screen layouts, and input responsiveness are important design
considerations. These need testing on real devices with different screen
sizes.

### ⚙️ Performance and Stability

Performance depends on device hardware, graphics settings, scene
complexity, memory use, and the quality of the Android build. The
project should be tested for loading behavior, stability,
responsiveness, and sustained performance before making compatibility
claims.

### 🏆 Independent Identity

SURVIVAL FORCE is an independent project, not an official version of
another game. It aims to develop its own implementation and use original
or appropriately licensed content.

We want to work toward a game experience that prioritizes:

-   🎯 **Classic-inspired atmosphere** --- capture the broad excitement

-   ⚙️ **Iterative engineering** --- use build logs, reproducible tests,

    has been generated and checked.

## ⚙️ Build Automation

The project aims to use GitHub Actions for repeatable Android build
attempts.

A properly configured workflow should:

1.  Check out the repository.
2.  Locate and validate the Unreal project.
3.  Confirm the required engine and Android tools are available.
4.  Run the appropriate Unreal Automation Tool build command.
5.  Package the Android target only if compilation and cooking succeed.
6.  Confirm that the expected APK exists and is non-empty.
7.  Upload the APK artifact only after those checks pass.
8.  Preserve build logs to make failures diagnosable.

### Unreal Engine environment requirement

Standard GitHub-hosted runners do **not** automatically include a
ready-to-use Unreal Engine 5.4 installation. The workflow needs an
environment where the engine is installed and accessible, such as a
properly configured compatible build machine or self-hosted runner.

A workflow YAML file alone cannot provide the full Unreal Engine
installation. Disk space, memory, engine access, Android dependencies,
build duration, and project errors can all affect success.

Build reports should reflect actual command output and artifacts---not
assumptions.
