## 馃幃 Project Overview

**SURVIVAL FORCE** is an independent Android game development project
focused on creating a survival shooter with a battle royale-style
experience.

Inspired by the excitement of classic-era mobile battle royale games,
SURVIVAL FORCE aims to build its own identity, gameplay implementation,
and mobile gaming experience. The project focuses on the thrill of
survival, tactical movement, combat encounters, exploration, and the
challenge of staying alive in a dangerous battlefield.

The project uses **Unity 2022.3 LTS** and **C#**, with Android as its
intended target platform.

Development involves project validation, gameplay implementation, asset
integration, Android packaging, and testing on real devices. Actual
gameplay features, successful compilation, APK generation, and device
compatibility must be verified independently.

> **Our principle:** Build carefully, test honestly, and only claim what
> has actually been verified.

## 鈿旓笍 Game Features and Vision

SURVIVAL FORCE is being developed around the core elements of a survival
shooter. The goal is to create an engaging experience where players
explore their surroundings, prepare for combat, make tactical decisions,
and fight to survive.

The features below describe the intended direction of the project. They
are not a claim that every feature is already implemented or playable.

### 馃敨 Combat and Weapon Systems

Combat is intended to be a central part of the experience.

The development direction includes:

-   Responsive shooting and aiming mechanics.
-   Weapon handling and combat interactions.
-   Clear feedback during combat encounters.
-   Gameplay balancing and improvements as systems develop.
-   Touch-friendly combat controls for Android devices.

Weapon types, firing behavior, damage systems, and other mechanics must
be verified in the running game before being described as complete.

### 馃帓 Loot and Equipment

Resource collection is intended to support survival and tactical
decision-making.

Potential development areas include:

-   Collecting useful items from the environment.
-   Managing equipment and available resources.
-   Connecting item collection with gameplay.
-   Improving the usability of inventory-related interfaces.

Actual inventory and equipment functionality depends on the systems
implemented in the project.

### 馃實 Battlefield and Exploration

The intended game experience includes environments where players can
explore, navigate, find resources, and encounter opponents.

Environment development focuses on:

-   Readable and navigable spaces.
-   Exploration and movement.
-   Combat encounters and tactical positioning.
-   Appropriate use of environmental assets.
-   Mobile performance and loading considerations.

The presence of an environment asset does not automatically mean that a
complete playable map exists.

### 馃獋 Survival Gameplay

Survival is the central theme of SURVIVAL FORCE.

The intended gameplay direction emphasizes:

-   Staying alert to nearby threats.
-   Making tactical movement decisions.
-   Managing available resources.
-   Choosing when to engage opponents.
-   Working toward a coherent match flow and victory condition.

The final gameplay experience will depend on the survival and match
systems that are implemented and tested.

### 馃 AI Opponents

AI-controlled opponents are an area of interest for the project.

Where supported by the implemented systems, AI development may include
opponent movement, combat behavior, and interactions with the player.

AI functionality must be tested in actual gameplay before it can be
considered complete.

### 馃摫 Mobile Controls and Interface

SURVIVAL FORCE is intended for Android, so touch interaction and screen
usability are important considerations.

Development and testing should consider:

-   Touchscreen movement and camera control.
-   Button placement and sizing.
-   Shooting and aiming interaction.
-   Different screen sizes and aspect ratios.
-   Interface readability.
-   Input responsiveness during gameplay.

The final control experience should be evaluated on physical Android
devices.

### 鈿欙笍 Performance and Stability

Mobile performance depends on hardware capabilities, graphics settings,
memory use, scene complexity, and implementation quality.

The project should be evaluated for:

-   Startup and loading behavior.
-   Rendering performance.
-   Memory usage.
-   Input responsiveness.
-   Stability during gameplay.
-   Device compatibility.
-   Heat and sustained performance.

No universal FPS or device-compatibility guarantee is made without
actual test results.

## 鈿欙笍 Build Automation

The project may support repeatable Android build attempts through
Unity's command-line build workflow or GitHub Actions, provided a
compatible Unity installation, Android modules, and licensing/activation
are available.

A properly configured workflow should:

1.  Check out the correct repository revision.
2.  Locate and validate the Unity project.
3.  Confirm the required Unity Editor version and Android build modules
    are available.
4.  Run Unity in batch mode with a configured Android build method.
5.  Stop if compilation or build steps fail.
6.  Confirm the expected APK exists and is non-empty.
7.  Upload the artifact only after those checks pass.
8.  Preserve build logs for diagnosing failures.

### Unity Build Environment Requirements

A standard GitHub-hosted runner does **not** automatically include the
exact Unity Editor version and Android modules required by this project.
Unity licensing or activation may also be required, depending on the
environment and license.

The build environment must have access to a compatible Unity
installation, Android SDK/NDK/JDK setup, and the project's build
configuration. A workflow file alone cannot install or license every
required component automatically.

Build reports should reflect actual command output and generated
artifacts.
