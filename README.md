## 🎮 Project Overview

**SURVIVAL FORCE** is an independent Android game development project focused on creating a survival shooter with a battle royale-style experience.

Inspired by the excitement of classic-era mobile battle royale games, SURVIVAL FORCE aims to build its own identity, gameplay implementation, and mobile gaming experience. The project focuses on the thrill of survival, tactical movement, combat encounters, exploration, and the challenge of staying alive in a dangerous battlefield.

The project is associated with **Unreal Engine 5.4** and **C++**, with Android as its intended target platform.

Development involves project validation, gameplay implementation, asset integration, Android packaging, and testing on real devices. Actual gameplay features, successful compilation, APK generation, and device compatibility must be verified independently.

> **Our principle:** Build carefully, test honestly, and only claim what has actually been verified.

## ⚔️ Game Features and Vision

SURVIVAL FORCE is being developed around the core elements of a survival shooter. The goal is to create an engaging experience where players explore their surroundings, prepare for combat, make tactical decisions, and fight to survive.

The features below describe the intended direction of the project. They are not a claim that every feature is already implemented or playable.

### 🔫 Combat and Weapon Systems

Combat is intended to be a central part of the experience.

The development direction includes:

- Responsive shooting and aiming mechanics.
- Weapon handling and combat interactions.
- Clear feedback during combat encounters.
- Gameplay balancing and improvements as systems develop.
- Touch-friendly combat controls for Android devices.

Weapon types, firing behavior, damage systems, and other mechanics must be verified in the running game before being described as complete.

### 🎒 Loot and Equipment

Resource collection is intended to support survival and tactical decision-making.

Potential development areas include:

- Collecting useful items from the environment.
- Managing equipment and available resources.
- Connecting item collection with gameplay.
- Improving the usability of inventory-related interfaces.

Actual inventory and equipment functionality depends on the systems implemented in the project.

### 🌍 Battlefield and Exploration

The intended game experience includes environments where players can explore, navigate, find resources, and encounter opponents.

Environment development focuses on:

- Readable and navigable spaces.
- Exploration and movement.
- Combat encounters and tactical positioning.
- Appropriate use of environmental assets.
- Mobile performance and loading considerations.

The presence of an environment asset does not automatically mean that a complete playable map exists.

### 🪂 Survival Gameplay

Survival is the central theme of SURVIVAL FORCE.

The intended gameplay direction emphasizes:

- Staying alert to nearby threats.
- Making tactical movement decisions.
- Managing available resources.
- Choosing when to engage opponents.
- Working toward a coherent match flow and victory condition.

The final gameplay experience will depend on the survival and match systems that are implemented and tested.

### 🤖 AI Opponents

AI-controlled opponents are an area of interest for the project.

Where supported by the implemented systems, AI development may include opponent movement, combat behavior, and interactions with the player.

AI functionality must be tested in actual gameplay before it can be considered complete.

### 📱 Mobile Controls and Interface

SURVIVAL FORCE is intended for Android, so touch interaction and screen usability are important considerations.

Development and testing should consider:

- Touchscreen movement and camera control.
- Button placement and sizing.
- Shooting and aiming interaction.
- Different screen sizes and aspect ratios.
- Interface readability.
- Input responsiveness during gameplay.

The final control experience should be evaluated on physical Android devices.

### ⚙️ Performance and Stability

Mobile performance depends on hardware capabilities, graphics settings, memory use, scene complexity, and implementation quality.

The project should be evaluated for:

- Startup and loading behavior.
- Rendering performance.
- Memory usage.
- Input responsiveness.
- Stability during gameplay.
- Device compatibility.
- Heat and sustained performance.

No universal FPS or device-compatibility guarantee is made without actual test results.

## ⚙️ Build Automation

The project aims to support repeatable Android build attempts using GitHub Actions where a compatible Unreal Engine environment is available.

A properly configured workflow should:

1. Check out the correct repository revision.
2. Locate and validate the Unreal project.
3. Confirm the required engine and Android tools are available.
4. Run the appropriate Unreal build commands.
5. Package the Android target only when compilation and cooking succeed.
6. Confirm the expected APK exists and is non-empty.
7. Upload the artifact only after those checks pass.
8. Preserve build logs for diagnosing failures.

### Unreal Engine Environment Requirements

Standard GitHub-hosted runners do **not** automatically include a ready-to-use Unreal Engine 5.4 installation.

The workflow needs a compatible environment where the engine is installed and accessible, such as a properly configured build machine or self-hosted runner.

Engine access, storage, memory, Android dependencies, build duration, and project errors can all affect success.

A workflow file alone cannot provide the full Unreal Engine installation. Build reports should reflect actual command output and generated artifacts.
